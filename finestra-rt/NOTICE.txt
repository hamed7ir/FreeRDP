This directory is NOT part of upstream FreeRDP. It is added by the Finestra fork to

--------------------------------------------------------------------------------
2. WHAT IS *NOT* HERE -- THREE PREBUILT LIBRARIES YOU MUST SUPPLY
--------------------------------------------------------------------------------
The ARM32 build links three static libraries that are NOT included in this repository:

    libcrypto.lib     OpenSSL 3.3.2, ARM32 (ARMNT), static /MT
    libssl.lib        OpenSSL 3.3.2, ARM32 (ARMNT), static /MT
    z.lib             zlib 1.3.1,    ARM32 (ARMNT), static /MT

Point the build at them with -DLIB_EAY_RELEASE, -DSSL_EAY_RELEASE and -DZLIB_LIBRARY
(see port/rt-configure-pins.txt for the full command).

How they were produced, recorded from the original build:

    OpenSSL 3.3.2:   perl Configure VC-WIN32-ARM no-asm
    zlib 1.3.1:      static /MT, same ARMNT toolchain

  *** This invocation is RECORDED FROM THE ORIGINAL BUILD AND HAS NOT BEEN
      RE-VERIFIED. *** Nobody has yet re-run it from scratch and confirmed it
      reproduces linkable libraries. A planned rebuild will confirm it; until then,
      treat it as the best available record rather than a tested procedure.

`no-asm` is not optional: the ARM32 assembly paths are not usable in this
configuration, and the generated headers in deps-headers/openssl-3.3.2 are configured
to match (see 4).

--------------------------------------------------------------------------------
3. rt-deps/libproviders.lib -- NON-OFFICIAL PREBUILT, AND WHAT IT IS FOR
--------------------------------------------------------------------------------
This is a NON-OFFICIAL, third-party-built static library. It is NOT distributed by the
OpenSSL project and carries no upstream guarantee. It is OpenSSL 3.3.2 code, licensed
Apache-2.0; the licence text is in LICENSE.OpenSSL-3.3.2.txt.

WHAT IT DOES: this OpenSSL 3.3.2 build split the default provider's ALGORITHM
IMPLEMENTATIONS into a separate archive. libproviders.lib is that archive -- 4,671
defined symbols covering the cipher, digest, KDF, MAC, RAND, keymgmt, signature and
encoder/decoder implementations. It does NOT define ossl_default_provider_init; that
symbol lives in libcrypto.lib (verified with llvm-nm: libcrypto defines it,
libproviders does not). Without libproviders.lib the link fails on the implementation
symbols, not on the init function.

REPRODUCIBILITY -- read both halves:

  * NOT reproducible from source. The build script that performed the separate-archive
    split no longer exists. Only the Configure flag list survives (section 2). Nobody,
    including the author, can currently regenerate this archive from OpenSSL sources
    and be confident of getting the same split.

  * IS re-archivable from its members. The archive contains exactly 163 object files,
    and those objects are self-contained: an identical-in-content archive can be
    rebuilt from them with
        llvm-ar rcs libproviders.lib <163 .obj files>
    That is a repack, not a rebuild -- it does not let you regenerate the objects
    themselves from source.

This is why the archive is vendored rather than merely documented: it is the one
component here that cannot currently be produced again from source.

--------------------------------------------------------------------------------
4. deps-headers/openssl-3.3.2 -- GENERATED HEADERS, NOT STOCK UPSTREAM
--------------------------------------------------------------------------------
These headers are the ones GENERATED by the `perl Configure VC-WIN32-ARM no-asm` run
described in section 2. OpenSSL's configuration step writes build-specific headers
(configuration.h records OPENSSL_NO_ASM, bn_conf.h the word size, and so on).

*** Stock upstream OpenSSL 3.3.2 headers are NOT a valid substitute. *** Building
against unconfigured or differently-configured headers while linking these libraries
produces mismatched assumptions -- the failure mode is silent misbehaviour, not a
compile error.

deps-headers/zlib-1.3.1 are the ordinary zlib headers matching z.lib.
